# Mini Project: เกณฑ์การให้คะแนน (Rubric)

คะแนนรวม **40 คะแนน** แบ่งเป็น **คะแนนกลุ่ม 30 คะแนน** (ระบบ การออกแบบ รายงาน และความยากของหัวข้อ) และ **คะแนนรายบุคคล 10 คะแนน** (สัมภาษณ์เทคนิคในคาบ Demo) — สมาชิกกลุ่มเดียวกันอาจได้คะแนนรายบุคคลไม่เท่ากัน

---

## ส่วนที่ 1: คะแนนกลุ่ม (30 คะแนน)

### 1.1 ระบบทำงานสมบูรณ์ (12 คะแนน)

| รายการ | คะแนน | ระดับต่ำ (0) | ระดับเต็ม |
| ------- | ----- | ------------- | --------- |
| FSM ทำงานครบทุกสถานะตาม state diagram/table ที่สเปกไว้ | 5 | FSM ขาดสถานะ ติดค้าง หรือเปลี่ยนสถานะผิดเงื่อนไข | ทุกสถานะและทุกเงื่อนไขเปลี่ยนทำงานถูกต้องตรงสเปก |
| ภาพบนจอ VGA ถูกต้องเสถียร ตรงตามสเปกที่เขียนไว้ | 5 | ภาพหลุด sync / วิบวับ / ไม่ตรงสเปก | ภาพนิ่งเสถียร ตำแหน่ง-สี-เนื้อหาตรงสเปกทุกข้อ |
| อินพุตที่เลือกใช้ (SW/KEY/GPIO/ADC) ทำงานตามสเปก | 2 | อินพุตบางตัวไม่ทำงานหรือไม่ตรงหน้าที่ที่สเปกไว้ | อินพุตทุกตัวที่ประกาศในสเปกทำงานครบถูกต้อง |

### 1.2 การออกแบบ VHDL (7 คะแนน)

| รายการ | คะแนน | ระดับต่ำ (0) | ระดับเต็ม |
| ------- | ----- | ------------- | --------- |
| แบ่ง module ชัดเจน (FSM / Drawing Logic / VGA Controller แยกกัน) | 3 | ทุกอย่างรวดในไฟล์เดียว แก้ต่อยาก | แต่ละบล็อกแยก entity ชัด ต่อกันด้วยสัญญาณชัดเจน |
| สไตล์โค้ดถูกหลัก — naming, `downto`, ประเภท architecture เหมาะกับงาน | 2 | ฝืนกันกับแบบที่เรียน อ่านเข้าใจยาก | naming สม่ำเสมอ vector ใช้ `downto` Structural/Dataflow/Behavioral เลือกถูกประเภท |
| นำชิ้นส่วนจากใบงานเดิมมา reuse (clock divider, counter, register, ฯลฯ) | 2 | เขียนซ้ำทั้งที่มีของเดิม | reuse ถูกจุด อธิบายได้ว่าดัดแปลงอะไร |

### 1.3 รายงาน (8 คะแนน)

| รายการ | คะแนน | ระดับต่ำ (0) | ระดับเต็ม |
| ------- | ----- | ------------- | --------- |
| สเปกโปรเจกต์ครบ 5 ข้อ (เป้าหมาย / FSM / I-O / หน้าจอ VGA / การทดสอบ) | 2 | ขาดหลายข้อ หรือเขียนกำกวม | ครบทุกข้อ ชัดพอให้คนอื่นนำไปทำต่อได้ |
| State diagram และ state table ถูกต้องตรงกับโค้ดจริง | 3 | diagram/table ขัดกับโค้ด | diagram/table ตรงกับวงจรจริงทุกสถานะ |
| Waveform + ภาพถ่ายบอร์ด/จอ ครบและยืนยันการทำงานได้ | 2 | ไม่มี หรือไม่สนับสนุนข้อสรุป | waveform ชี้จุดพิสูจน์ได้ + ภาพถ่ายชัดทุกกรณีทดสอบ |
| ปัญหาที่พบและวิธีแก้ + บทบาทสมาชิก | 1 | ไม่มี | ระบุปัญหาจริง วิธีแก้ และแบ่งบทบาทชัดเจน |

### 1.4 ความยากของหัวข้อ (3 คะแนน)

ประเมินเป็นระดับ — **ไม่ลงโทษหัวข้อง่าย** (ทำสมบูรณ์ก็ได้เต็มส่วนอื่นได้) แต่ให้แรงจูงใจกับหัวข้อที่ท้าทายขึ้น:

| ระดับ | คะแนน | ตัวอย่าง |
| ----- | ----- | -------- |
| พื้นฐาน — ใช้เฉพาะ SW/KEY, ภาพนิ่งหรือเปลี่ยนตามสวิตช์ตรงไปตรงมา | 0 | แสดงรูปทรงตามสถานะสวิตช์ |
| ดี — มีตรรกะเปลี่ยนตามเวลา/คะแนน หรือ FSM มีมากกว่า 4 สถานะ | 1 | scoreboard นับเวลา, เกมจับคู่ |
| ดีมาก — มี animation ต่อเนื่อง ตรรกะเกมซับซ้อน หรือหลายฉาก | 2 | Pong เด้งลูกบอล, สล็อตแมชชีน |
| ท้าทาย — ใช้ ADC/GPIO ภายนอก หรือความซับซ้อนเทียบเท่า | 3 | โวลต์มิเตอร์/bar-graph จาก ADC, เกมควบคุมด้วย potentiometer |

## ส่วนที่ 2: คะแนนรายบุคคล (10 คะแนน ต่อคน)

ประเมินจากการสัมภาษณ์เทคนิคในคาบ Demo — สมาชิกแต่ละคนตอบทั้งส่วนที่ตัวเองรับผิดชอบและภาพรวมของระบบ:

| รายการ | คะแนน | เกณฑ์ |
| ------- | ----- | ----- |
| อธิบายส่วนที่ตัวเองรับผิดชอบ (โค้ด/บล็อกที่เขียน) | 5 | อธิบายได้ลึกถึงระดับสัญญาณ/process ไม่ใช่แค่ความหมายรวม ๆ |
| อธิบายภาพรวมระบบ รวมส่วนที่เพื่อนรับผิดชอบ | 3 | เชื่อมโยงบล็อกและการไหลข้อมูลทั้งระบบได้ |
| ตอบสถานการณ์สั้น ๆ (เช่น "ถ้าจะเพิ่มระดับความยาก ต้องแก้ FSM ตรงไหน") | 2 | วิเคราะห์ผลกระทบต่อวงจรได้ถูกต้อง |

> การสาธิต (Demo) บนบอร์ดให้อาจารย์ตรวจถือเป็นส่วนหนึ่งของข้อ 1.1 — ถ้าระบบไม่สามารถสาธิตได้ในคาบ ให้พิจารณาจากหลักฐานในรายงานตามความเหมาะสม
